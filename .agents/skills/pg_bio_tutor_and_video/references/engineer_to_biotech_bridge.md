## 2. Standard Analogies for Video Scripts & Tutoring

When explaining why `pg_bio` exists to software engineers, emphasize the **3 Laws of In-Database Bioinformatics**:

1. **Move Compute to Shared Buffers, Not Data Over Sockets:**
   * A 3,000-atom PDB file or 1280-float ESM-2 vector lives in PostgreSQL 8KB pages (`Toast` / `Heap`). Pulling 100,000 rows over `psycopg` to Python means TCP serialization, UTF-8 decoding, `PyObject` boxing, and NumPy array copying—spending 99% of wall-clock time on plumbing rather than math.
2. **Use the Query Planner as a Multi-Stage Biological Sieve:**
   * Cheap $O(\log N)$ index filters run first (`HNSW <=>` or `B-Tree z_order_encode` or `GiST numrange @>`), pruning millions of candidates down to a handful *before* expensive $O(N)$ physics (`kabsch_rmsd`, `smith_waterman_score`, `evaluate_chaperone_block`) ever execute via `CROSS JOIN LATERAL`.
3. **Every Physical Constraint Is a SQL Predicate:**
   * In modern synthetic biology (like RosettaCommons Chaperone or Baker-lab theozyme design), designing a working protein is a **multi-objective filter query** over geometry, electrostatics, thermodynamics, and host genetics. SQL is the natural declarative language for multi-constraint scientific discovery.
